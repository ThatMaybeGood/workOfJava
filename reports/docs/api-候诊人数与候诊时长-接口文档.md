# 候诊人数与候诊时长 数据接口文档

> 需求方（我方）按日期向贵方请求门诊候诊统计数据，由贵方计算后返回：候诊总人数、平均候诊时长两个总指标，候诊人数按小时变化、候诊时长按科室两个明细列表。
> 接口形态（HTTP 方式、鉴权）由贵方现有规范决定，本文只约定数据内容。

---

## 1. 需求指标

| # | 指标 | 形态 | 说明 |
|---|------|------|------|
| 1 | 候诊总人数 | 数值 | 指定日期当天的候诊总人次 |
| 2 | 平均候诊时长 | 数值 | 指定日期当天的平均候诊时长（分钟） |
| 3 | 候诊人数时间变化 | 列表 | 当天 8:00–17:00，按 1 小时间隔（08:00–09:00 … 16:00–17:00，共 9 个区间）的候诊人次 |
| 4 | 候诊时长按科室 | 列表 | 各科室的平均候诊时长（分钟） |

日期由我方传入，总指标均指传入日期当天；以上指标请贵方计算好后返回。

## 2. 请求

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| date | string | 是 | 查询日期，格式 `yyyy-MM-dd` |

## 3. 响应结构

响应分三部分：两个总指标为平铺数值，两个明细为列表。

| 字段 | 类型 | 说明 |
|------|------|------|
| date | string | 日期 |
| total_wait_count | number | 总指标1：当天候诊总人次 |
| avg_wait_minutes | number | 总指标2：当天平均候诊时长（分钟） |
| hourly_wait_count | array | 明细1：候诊人数按小时变化，9 个元素 |
| hourly_wait_count[].hour | string | 区间起始小时，如 `08:00`（即 08:00–09:00 区间） |
| hourly_wait_count[].count | number | 该区间候诊人次 |
| dept_wait_duration | array | 明细2：候诊时长按科室 |
| dept_wait_duration[].dept_code | string | 科室编码 |
| dept_wait_duration[].dept_name | string | 科室名称 |
| dept_wait_duration[].avg_wait_minutes | number | 该科室平均候诊时长（分钟） |

## 5. 口径约定（请贵方确认）

1. **候诊时长 = 接诊时间 − 签到时间**（分钟）。若贵方系统无"签到"概念，以挂号有效时间/取号时间替代，请告知实际取值。
2. **小时区间口径**：候诊人次按**签到时间落在区间内**统计（如 08:31 签到计入 08:00 区间）；若贵方习惯按接诊时间或其他口径统计，请说明。
3. **未接诊记录**：不计入平均候诊时长；是否计入候诊总人数请贵方说明。
4. **时间范围**：仅门诊（8:00–17:00），急诊、体检、互联网诊疗请排除。
5. **跨天候诊**：当天签到次日才接诊的，请按当天口径处理（接诊超次日 06:00 视为未接诊），避免时长被异常拉大。
