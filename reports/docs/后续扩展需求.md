## 一、报表当日数据自动刷新（讨论于 2026-11-17，暂不实施）

### 背景与定位

报表数据会被拿去做决策，不能完全依赖用户手动点查询；但**只有当日数据会变**，历史日期基本不变。
因此只需要「页面开着、且当前查询的结束日期是今天」时，按报表配置的间隔自动补一次查询。

定位是**附加功能**：默认所有报表都不开，逐个报表在配置里显式打开。纯前端实现，后端零改动。

### 已定的口径

| 项 | 结论 |
|---|---|
| 触发条件 | 报表在配置里写了 `refreshMinutes`，且当前查询 `endDate === 今天`（按日历日期比较，跨日范围只要结束日是今天也算） |
| 间隔 | 每报表独立配置，单位分钟；不是全站固定值 |
| 计时基准 | **上一次请求结束时间**；手动查询、翻页、切筛选触发的查询都算，效果是「无人操作满 N 分钟补刷一次」 |
| 请求方式 | 静默：不显示 loading 遮罩、不清空表格、不重置分页/滚动位置、图表关动画 |
| 失败处理 | 立即暂停定时器，不 `alert`、不重试；页面提示「自动刷新已暂停」。理由：正常请求是通的，全网失败属于后端故障，自动重试没有意义 |
| 非当日 | 定时器停掉，页面提示「仅当日数据支持自动刷新」 |
| 页面不可见 | 暂停；切回来时若距上次已超间隔则立即补刷一次，否则等剩余时间 |
| 可感知性 | 页面显示「更新于 HH:mm:ss」 |
| 用户开关 | 不做 UI 开关，配置字段就是开关（数据用于决策，不应随手关掉） |
| 关闭页面 | 定时器随文档卸载消失，服务端无任何定时任务 |

### 配置放哪儿（关键结论）

放在 `reports-web/api-config.js`，原因是：22 个报表页 + `index.html` **全都已经引了它**，而 `main-app.js` 只有壳引、报表页引了会因绑定 `#sidebarToggle` / `#shellMockToggle` 报错。

现状：菜单配置现在在 `main-app.js:6-41`（`menuConfig`），需先迁到 `api-config.js` 的 `REPORTS_CONFIG`，并加上 `refreshMinutes` 字段（与已有的 `hidden` 字段同一份配置）。

```js
// ==================== 报表清单 ====================
// 菜单顺序、hidden 隐藏入口、refreshMinutes 自动刷新间隔(分钟, 不写=不刷新)都在这里
const REPORTS_CONFIG = {
    menu: [
        {
            group: '门诊报表', icon: 'bi-hospital-fill',
            items: [
                { label: '门诊运行数据统计', file: 'outpatient/outpatient-operation.html', icon: 'bi-graph-up' },
                { label: '人工窗口统计',     file: 'outpatient/outpatient-window-stats.html', icon: 'bi-shop', refreshMinutes: 5 },
                { label: '专科治疗量',       file: 'outpatient/outpatient-specialty-treatment.html', icon: 'bi-activity', hidden: true },
                // ...
            ]
        },
        // 住院报表 ...
    ]
};

// 按文件名取当前页配置(报表页用)
function getReportConfig(file) {
    const page = (file || location.pathname).split('/').pop();
    for (const group of REPORTS_CONFIG.menu) {
        for (const item of (group.items || [])) {
            if (item.file.split('/').pop() === page) return item;
        }
    }
    return null;
}
```

`main-app.js` 改为 `const menuConfig = REPORTS_CONFIG.menu;`，`visibleItems` / `renderMenu` / 默认页逻辑不动。

### 调度器实现要点

`setTimeout` 而非 `setInterval`（慢查询时不会堆积请求）；每次取数结束调 `schedule()` 重新计时。

```js
class AutoRefresh {
    constructor(task, intervalMs = 5 * 60 * 1000) {
        this.task = task;              // 取数函数, 返回 Promise (即 loadData)
        this.intervalMs = intervalMs;
        this.enabled = false;
        this.timer = null;
        this.running = false;
        this.lastRunAt = Date.now();

        document.addEventListener('visibilitychange', () => {
            if (document.hidden) this.clear();
            else if (this.enabled && Date.now() - this.lastRunAt >= this.intervalMs) this.run();
            else this.schedule();
        });
    }

    setEnabled(v) {
        if (this.enabled === v) return;
        this.enabled = v;
        if (v) this.schedule(); else this.clear();
    }

    // 每次取数结束(手动或自动)后调用, 以"上次请求结束"为基准重新计时
    schedule() {
        this.clear();
        if (!this.enabled || document.hidden) return;
        const wait = Math.max(0, this.intervalMs - (Date.now() - this.lastRunAt));
        this.timer = setTimeout(() => this.run(), wait);
    }

    clear() { clearTimeout(this.timer); this.timer = null; }

    async run() {
        if (this.running) return;
        this.running = true;
        try {
            await this.task();
        } catch (e) {
            console.warn('[auto-refresh] 刷新失败, 自动刷新已暂停', e);
            this.setEnabled(false);    // 失败直接暂停, 不重试
        } finally {
            this.running = false;
            this.lastRunAt = Date.now();
            this.schedule();
        }
    }
}
```

页面接入（以 `outpatient-window-stats.html` 为例，3 行）：初始化时按 `getReportConfig()` 创建、`loadData` 的 `finally` 里 `schedule()`、切换筛选后按 `endDate === 今天` 调 `setEnabled()`。

### 实施步骤

1. 菜单配置从 `main-app.js` 迁到 `api-config.js` 的 `REPORTS_CONFIG`，`main-app.js` 改为引用——这一步做完页面行为必须与迁移前完全一致，先单独验证。
2. 写 `AutoRefresh` 调度器（可并入 `api-config.js`，也可单独 `refresh-scheduler.js`），仅当 `getReportConfig().refreshMinutes > 0` 时创建。
3. 先只给一个报表配 `refreshMinutes` 做试点（人工窗口统计页面结构最简单，无分页无弹窗，适合验证机制）。
4. 试点稳定后再逐个报表接入，接入时重点验证该页 `loadData()` 是否可安全重复调用（有些页面在 `loadData` 里重建下拉选项、重置筛选、重新初始化图表，重复调用可能出错或闪烁）。

### 风险与注意事项

- **HIS 压力**：直查 HIS 的报表（收费员结账统计、院前转住院等）冷缓存一次可能几十秒。若确实压库，缓解手段是在后端加同一查询参数 60~120 秒的短 TTL 缓存——属于可选优化，等有实际数据再决定。
- **浏览器节流**：后台标签页的 `setTimeout` 会被延迟，靠 `visibilitychange` 回来时补刷兜住；电脑睡眠恢复同理。
- **同一用户开多个标签页**会各刷各的，各算各的间隔，一般无需合并。
- **Mock 模式**下也会刷（刷 mock 数据），无害；如需可加 `!API_CONFIG.useMock` 条件。

### 未决项

- 自定义跨日范围（如「11-10 ~ 今天」）是否算当日：暂按 `endDate === 今天` 即算；若嫌重可收紧为 `startDate === endDate === 今天`。
- 打开钻取弹窗、导出这类不发请求的操作是否也要推迟刷新（调 `delay()` 把 `lastRunAt` 置为当前时间），避免「看着弹窗时后台数据悄悄变了」。
